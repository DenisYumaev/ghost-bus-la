## 1. What does this do?

Why does the API's DNS record point at an Elastic IP instead of the VM's public IP?

**Your answer:**

>

<details>
<summary>Model answer</summary>

The auto-assigned public IP changes on every stop and start (the resize itself changed it). An Elastic IP stays with the account and is re-associated with the instance, so `api.<domain>` keeps working through restarts and resizes. Associating it also replaces the auto-assigned address, so outbound traffic uses it too.

</details>

## 2. What does this do?

Why is port 80 open when the API is only served over HTTPS?

**Your answer:**

>

<details>
<summary>Model answer</summary>

Caddy gets its certificates from Let's Encrypt, whose HTTP-01 challenge connects on port 80, and Caddy redirects plain HTTP to HTTPS. Closing 80 would break certificate issuance and renewal (unless switching to DNS challenges, which need registrar API credentials on the VM).

</details>

## 3. What breaks if…

…the plan had shown `aws_instance.app must be replaced`?

**Your answer:**

>

<details>
<summary>Model answer</summary>

A replacement creates a new VM and destroys the old one, with its root volume (`delete_on_termination`) and any spooled snapshots not yet uploaded, and termination protection would block it midway. That is outside the approved scope, so the apply stops and the owner is asked. A type change on an EBS-backed instance is an in-place stop, modify, start.

</details>

## 4. What breaks if…

…the security group also allowed port 22 "just for debugging"?

**Your answer:**

>

<details>
<summary>Model answer</summary>

It opens a brute-force and exploit surface for no need: shell access is through SSM Session Manager, which needs no inbound port and is logged through IAM. The test `security_group_opens_only_caddys_ports` fails on any rule covering 22.

</details>

## 5. How would you change it to…

…resize without losing any snapshots, given hard rule 3 (at most one snapshot interval of downtime)?

**Your answer:**

>

<details>
<summary>Model answer</summary>

With one VM you can't: a type change needs a stop. You would run a second ingest temporarily (bronze keys are content hashes written with If-None-Match, so two writers deduplicate), resize the first, then stop the second. That breaks "one instance" briefly, which is why the resize was instead done at about 1:30 AM Pacific, the quietest hour, and the gap is recorded.

</details>
